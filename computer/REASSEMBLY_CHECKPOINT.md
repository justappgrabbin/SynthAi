# Synthia Computer reassembly checkpoint

Run from this directory: `npm run install:shell`, `npm run build`, then `npm start`. The local desktop is served at `http://127.0.0.1:8765`.

The Kimi Web Linux desktop is copied from the user's original ZIP. Its shipped app registry has Files, Import, Synthia, Code Editor, and Text Editor. The original Kimi archive is preserved in `donors/source-archives/kimi-web-linux-original.zip` (SHA-256 `71e333c4962f1cc9dab0c67f0779dd1122cf606b59c3746efe3094625b8e76ee`). Unshipped Kimi demo apps remain in that original archive and are not in the compiled desktop.

The patched v0.5.1 execution spine is copied to `engines/unified-execution-spine`. It retains the operator, automata, state-space, reducer, execution and composition modules. The source v0.5.1 ZIP SHA-256 is `3ec10122d0e35aa9022aaceb4db4f6df795f5ae256d16a84922c05c75f049f82`; its supplied patch archive SHA-256 is `71af421b0e8ed9c6ed135b7b244c31bbe6c69b45b83a1b9a0724c87fb5df9365`. The donor Morph Chat under `donors/Back-up-` calls AutoLing and DISEMINER through its shared tool bridge. The local SynthiaSystem learning/contact call and the execution spine share the Computer's persisted state.

Import saves exact bytes in the Computer VFS, derives a computational state-space address, registers a file node in the execution bridge's capability mesh, registers code pieces with the recovered CodeDNALearner and EmergentMesh, and binds a VQ-VAE cue to an ATO recall automaton. Clicking an imported item fires that automaton and verifies the exact address and SHA-256 before content is returned. VQ-VAE is a recognition hint, never the authority or sole copy of a file. ZIP members each get their own address; paths and source archive are preserved. Code execution can resolve an existing address and records the 11 pipeline stages and a receipt. The Kimi Files and editors persist their desktop filesystem through the Computer state store.
