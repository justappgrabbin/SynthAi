# Venom and Hover phone runtime repair

The working branch is based on `integrate/canonical-hover` (`f1b31b8`). The
installed applications remain Android phone computers with embedded Linux.

## Executable changes

### Request-driven world revision

The follow-up preserves Dream Habitat's real simultaneous grammar kernel and
corrects swarm units to carry all five projections at once, with sourced
macro/micro descriptions, weighted edges and Space as observer. Source review is
recorded in [the morph source audit](SOURCE-MORPH-AUDIT.md).

The preset selector has been replaced by a once-per-profile world request.
Successful choices persist with their executable host grammar; failed requests
do not consume the choice. Visitors, local NPCs and shared participants adopt the
host's form, while identity/photo and their own home choice remain unchanged.
Public-place grammar works through the same visitor contract. The local five-field
compiler builds procedural rainbow, butterfly, flower, star and crystal geometry
in independent structural/inhabitant combinations. Requests requiring other
assets explicitly remain unresolved. This is not unrestricted neural asset
generation or a finished iOS runtime; see [acceptance status](MORPH-ACCEPTANCE.md).
The earlier palette implementation below describes the original adapter only.

Venom now launches the actual supplied Resonance Network Python API, React
frontend, and opportunity service under restart supervision. It uses the bundled
JPL ephemeris and a persistent private SQLite database. The 74,697,605-byte source
archive's identity and exclusions are recorded in its donor `SOURCE.json`.
Installation caches, unrelated reference data and old installation configuration
are excluded; the application runtime is preserved.

The actual Consciousness Realm Three.js app is built into Venom assets. It has
touch movement/jump/interaction controls, compact field controls, world themes,
and an avatar/address overlay. The photo adapter makes a twelve-pose illustrated
sprite sheet with the supplied skeletal surface morph engine and preserves the
photo in each pose. It fills transitions between states and supports importing
an authored sprite sheet. It does **not** generate a photorealistic person from
a photograph. Chair actions have concrete sit/stand/lift/throw effects and
temporary avatar states, with interaction relationships recorded in the mesh.

World themes change ground/path materials, lighting, fog, atmosphere and avatar
presentation without replacing object identities or game affordances. Entering
a host world retains the visitor's identity and photograph.

The network app supplies real chart coordinates to the backend. Source fields
that it does not supply (natal dimension and house) remain unresolved. Binary,
ASCII, NATO, transliteration and Unicode are derived from those exact coordinates.
The inspector exposes their sentence, King Wen/Fu Xi bit/bigram/trigram/hexagram
structure, and the preserved semantic-mesh color and sound mappings. Rendering
projections are explicit and do not rewrite unresolved source coordinates.

The swarm uses the preserved YOU-N-I-VERSE dimensional operators and actual
address pieces. It produces visible hexagram structures and orbiting expression
pieces at Being and above. Its coherence is a symbolic simulation metric.

`Host my world` starts an invitation-protected session service; `Join world`
connects another computer. Sessions exchange public resolved address states and
movement, with host grammar applied to guests. Invitations work on reachable
networks, including the same Wi-Fi; no public relay or NAT traversal is deployed.
Birth data and avatar photographs are not transmitted. Each participant receives
a separate session credential, identities cannot change within a session, and
offline participants expire. Physical two-phone acceptance is still required.

Hover's existing contact/neural organs and birth resolver remain authoritative.
Normal chat now passes available phone perception and concrete native action
receipts through cognition. New tasks are automatically queued, and the worker
uses that same contact path. Failed actions are rejected; successful dispatch
does not assert completion of arbitrary user goals. Accessibility-dependent
actions still require the Android service to be enabled by the phone owner.

## Memory and Modelmaker

Realm observations persist as raw episodes plus learned connection-field state.
VQ-VAE is reserved for episodic memory. The supplied VQ-VAE donor is an image
model and training pipeline; no trained checkpoint was supplied. It is preserved
as source and is not mislabeled as working episodic inference or used for avatar
generation. The runtime reports `TRAINED_CHECKPOINT_REQUIRED`.

The supplied York ZIP is an Android launcher/build script. The later identified
[Modelmaker Space](https://huggingface.co/spaces/stellarproximology/Modelmaker)
has a Gradio `app.py` configuration and TypeScript application sources, but no
`app.py` at the inspected revision. The
[Modelmaker-repair](https://github.com/justappgrabbin/Stellarproximology-lab/tree/main/Modelmaker-repair)
package trains a GPT-style text model. That does not implement the requested
contact model, image morph training, or episodic VQ-VAE backend. Neither service
has been silently replaced or deployed by this repair.

The Drive library's `semantic-dna-swarm (1).html`
(`1VaDdlmpLpTFMaXEdPHZrUsVnGvSHCoU_`) was inspected. Its preserved semantic-mesh
sound/color mappings are already present in canonical Hover; the required modules
are copied exactly into the Venom donor.
