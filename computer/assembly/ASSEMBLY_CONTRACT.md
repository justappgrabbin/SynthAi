# SynthAI Computer + Resonance Network | Assembly contract

**Status:** Repository foundation established. This document is an intake and acceptance contract, **not** evidence that the supplied applications have been integrated or tested inside the Computer.

**Host:** `justappgrabbin/SynthAi`, directory `computer/`. This branch starts from `reassembly/computer-2026-09-29`, keeping the existing Computer runtime, donor history, desktop shell and Android source. `main` and the reassembly source branch must not be rewritten to perform assembly.

## Non-negotiable source-preservation rules

1. Assemble the user-supplied implementations. No invented replacement dashboard, pretend service, or substitute engine.
2. Audit provenance, actual behavior, interfaces, data flow, runtime prerequisites and limitations **before** modifying a source. Separate verified behavior from intended behavior.
3. Preserve complete original project archives unchanged and retain version lineage. Installed components must be whole, not stripped to a few UI files. Loading components on demand is permitted, silent omission is not.
4. **Resonance Network exception:** integrate the union of every unique piece across all supplied RN versions. Byte-identical working files may share one executable instance if all originals and provenance survive. Same-path code with different behavior is **not** identical; both versions must be accounted for and reconciled explicitly.
5. Never silently delete, replace or rewrite landed history. Rollback creates a new descendant, not erased history. Every source and behavior change gets a recorded rationale.
6. Preserve Synthia's real chat, speech/listening and meaningful event-driven behavior. A silent façade does not satisfy integration.
7. Prioritize existing **user-useful working functionality**, including actual Resonance Network flows, existing cultivation components, and Human Design engines, over speculative new features. Missing self-cultivation behavior is a *gap for later definition*, not permission to fabricate it.
8. Each pass must open into a useful Computer experience with operable actions and observable outcomes, not a blank shell or menu of unconnected promises.
9. The Computer remains one coherent product. Resonance Network lives **inside** the Computer with appropriately separated social, research, experimentation, creation and community surfaces. Follow the existing Computer interface and design references; no generic template redesign.
10. Imagery and final visual refinement come **after** functionality. When added, images must be real preserved/generated assets rendered in the product; no dots, orb stand-ins or placeholders presented as complete.
11. Report what is PRESENT, WIRED, TESTED, FAILED, DEFERRED and NOT FOUND with concrete evidence. Do not call a UI registration a runnable installation, a passing unit test a live integration, or a successful APK build a verified visible phone app.
12. For APK delivery, verify installed-app launch, nonblank visible home, file intake, persistence, app mounting, Synthia interaction and critical Resonance flows on a real/supported Android runtime; clearly disclose any checks not performed.

## Assembly order and completion criteria

- **Source mapping:** record every original archive, exact hashes, distinct files/behaviors, entrypoints, dependencies, tests, callers and potential overlap. Do not infer real behavior from README claims alone.
- **Host verification:** run inherited Computer tests, desktop HTTP/visible functionality checks and record existing Android status **before** introducing new donor changes.
- **Existing capabilities first:** connect and test concrete intake, memory, computer shell, Synthia conversation/voice, Resonance social/research, available cultivation components, HD engines and IDE components using their actual source code and adapters.
- **RN uniqueness reconciliation:** maintain a per-component ledger of every RN unique item across versions, preserving conflicts and original archives; no item is considered included solely because its source exists somewhere.
- **Phone acceptance:** test actual Android output and the on-screen user flows. Build output size is not acceptance evidence.
- **Visual finish last:** refine layout, proportions, photography/illustration and interactions while respecting original screens and mechanical completeness.
