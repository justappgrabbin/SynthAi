# Run Synthia with her own Modelmaker-trained language model on Linux

This is the native **Modelmaker → Synthia Computer** integration route,
without substituting a downloaded generic chat model.

**Sources**:
- Synthia Computer: `justappgrabbin/SynthAi`, this branch.
- Original Modelmaker trainer: `justappgrabbin/Stellarproximology-lab/Modelmaker-repair/app.py`.
- Modelmaker integration branch: `integration/modelmaker-synthia-local-inference-20261027`.
- Modelmaker inference service: `Modelmaker-repair/synthia_server.py`.
- Synthia's existing `SynthiaLanguageModel` already speaks
  `POST /v1/chat/completions`; no competing model runner is introduced.

## Linux: build your own weights

In a local clone of `Stellarproximology-lab`:

```sh
git switch integration/modelmaker-synthia-local-inference-20261027
cd Modelmaker-repair
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python app.py
```

The Gradio interface trains a GPT-2-shaped causal model from supplied
text/files and produces a ZIP containing `model.safetensors`, tokenizer
files, `config.json` and `modelmaker_build.json`. The GPT-2 label
shift is fixed on this integration branch.

Export the model ZIP from the training UI. Extract it into a private
local folder. For example, a Modelmaker export named `synthia-seed.zip`
can be extracted into `$HOME/.local/share/synthia/modelmaker/synthia-seed/`.

**Do not** feed sensitive Computer state, private conversations or
someone else's records into the trainer without appropriate consent.
A toy model trained from a few paragraphs will produce toy results.

## Linux: run your trained checkpoint

From the **same** `Modelmaker-repair` environment:

```sh
python synthia_server.py \
  --model-dir "$HOME/.local/share/synthia/modelmaker/synthia-seed" \
  --port 11734
```

This loader:
- Requires a real local GPT-2 Modelmaker export and reads its
  `model.safetensors` using Transformers with `use_safetensors=True`,
  `local_files_only=True` and `trust_remote_code=False`.
- Does not download a base model, overwrite weights, train during inference,
  execute tools or accept user-supplied checkpoint paths in HTTP requests.
- Listens on **127.0.0.1 only** and exposes `/health`, `/v1/models`
  and `/v1/chat/completions`.
- Bounds request size, context and output token count. Long prompts are
  truncated from the left to fit a small training context.

Validate the model process:

```sh
curl --fail http://127.0.0.1:11734/health
curl --fail http://127.0.0.1:11734/v1/models
```

Both commands check the local **model service**, not yet a Synthia conversation.

## Linux: connect the existing Computer

In a **second terminal**, inside a clone of `SynthAi`:

```sh
git switch integration/synthia-native-modelmaker-20261027
git submodule update --init --recursive

export SYNTHIA_LLM_BASE_URL=http://127.0.0.1:11734/v1
export SYNTHIA_LLM_MODEL=synthia-seed
export SYNTHIA_LLM_TIMEOUT_MS=60000

npm --prefix computer run install:shell
npm --prefix computer run build
npm --prefix computer start
```

Inspect status and send a real Computer message:

```sh
curl --fail http://127.0.0.1:8765/api/synthia/status
curl --fail -H 'Content-Type: application/json' \
  --data '{"text":"Hello Synthia. What can we learn together?"}' \
  http://127.0.0.1:8765/api/chat
```

A verified response must contain:
- `model.used: true` and `provider: "llm:openai-compatible"`;
- `klein.passedToModel: true` and `klein.executed` showing AutoLing and
  DISEMINER;
- `resident.toolEvidence` with actual AutoLing/DISEMINER execution;
- A nonempty `text` generated by the locally trained model.

If the model fails or returns empty text, Synthia falls back to her existing
Morph Chat response and marks `model.used: false` plus
`model.fallbackReason`. A ready health endpoint does not prove language
quality or that the full Computer is working.

## Architecture / memory preservation

```
Your Modelmaker training corpus → GPT-2 training → model.safetensors
         ↓
Modelmaker's read-only local Python inference (127.0.0.1:11734)
         ↓  /v1/chat/completions
Synthia Computer /api/chat (127.0.0.1:8765)
   ↓
Original Klein AutoLing + DISEMINER and Synthia neural intent graph
   ↓ structured, bounded evidence
Original SynthiaLanguageModel → locally trained checkpoint
   ↓
Computer response, resident semantic state and event receipt
```

The local resident's weights (`computer.synthia.resident.v1`) and
the independent Simlish multimodal checkpoint (`.npz`) remain separate.
No automatic fine-tuning, interchange of tensor shapes, or overwrite
is performed. Modelmaker's GPT-2 checkpoint is **third, distinct** weight
family. Its tokenizer and config must travel with its weights.

**Security note:** The Computer's loopback API has powerful operations.
Do not publish or port-forward either service without an authenticated
access boundary. Preserve private state backups before using new builds.

## Verification

- `Stellarproximology-lab` has Python tests for input validation,
  HTTP interoperability, and a CPU train → export → reload → generate smoke.
- `SynthAi` has a Node regression test for model provenance and Klein
  grounding while the resident's weight state remains unchanged.
- Real interactive Linux use, model quality and host memory consumption
  remain **unverified until run on your computer**.
