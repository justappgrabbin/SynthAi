# User-requested local morph: acceptance criteria

The original palette and skeletal photo renderer did not fulfill this feature.
Cosmic, Aurora, Garden and Noir were implementation choices, not approved scope.
Custom appearance definitions removed the preset gate but did not solve request
understanding or asset generation.

## Implemented request and residency behavior

The phone now accepts one successful initial world request per resolved profile.
The chosen grammar and its lock are stored together and survive restart. Failed
requests do not use the choice. Requests queued concurrently cannot overwrite a
successful choice. Photo and authored animation updates remain available.

A portable local procedural compiler separates Movement, Evolution, Being,
Design and Space outputs. It composes structural and inhabitant primitives rather
than choosing a complete preset. "Butterflies and rainbows" produces rainbow
arch structures and winged butterfly bodies. Explicit role sentences allow
independent combinations. Flowers, stars and crystals have local geometry
builders; humans retain the photo/sprite body. Source addresses determine scene
placement and scale. The chosen host supplies visitor/NPC bodies; the photo and
address remain the visitor's identity. A public place supplies its grammar, and
returning home restores the person's own form. Exported 12-state sheets follow
the current host's form.

This is procedural illustration, not photorealistic photo-conditioned neural
generation. Unknown vocabulary or unresolved subjects produce an explicit error;
the system does not pretend to satisfy them or consume the choice. Open-ended
asset synthesis and native generation/inference integration remain outstanding.
The portable compiler is JavaScript; the current host server is Node on Android's
container. There is still no working iPhone host implementation.

Validation: 96 Computer tests; real two-computer room protocol inheritance;
Realm renderer build; 390-pixel phone rendering with real Resonance profile,
rainbow geometry, butterfly bodies, retained photo and actual chair interactions.
No physical Android or iPhone acceptance test has been performed.

The replacement must:

1. Accept the user's change request in the phone computer and resolve it locally.
2. Produce visible character and world changes, including requested appearance,
   objects and scenery; storing a description or changing a palette is not success.
3. Use the user's photo as identity input and preserve recognizable identity
   across chosen worlds and host-world adaptations.
4. Generate consistent core sprite states and retain a stable identity independent
   of objects. Temporary object interactions connect through the relational mesh
   and produce the required intermediate morph states and return state.
5. Express the world through the addressed swarm and host dimension rules,
   preserving source addresses rather than inventing chart coordinates.
6. Execute inside the Android and iPhone computers. A renderer may be embedded, but a remote
   browser service cannot silently replace local computation.
7. Distinguish request interpretation, asset generation, validation, application
   and failure. Never report a change as applied before it renders. Keep the
   previous working character and world on failure.
8. Verify representative changes against rendered output on the target phone,
   including latency, memory use, identity continuity and object interaction.

There are no trained identity-conditioned image generation weights or local
open-ended request-to-scene model in the inspected payloads. Existing donor
GameMorpher returns a recipe, not a rendered world. Existing SpriteMorpher returns
a tween rig plan, not generated identity-consistent sprites. The provided surface
morph engine can interpolate known endpoints, but cannot generate those endpoints
from an arbitrary request. These are replacement/integration requirements, not
reasons to redefine the user's request as a preset selector.

Android and iPhone are required platforms. The current Android Linux container
is not an iOS execution strategy; the morph generation runtime must be portable
with native inference implementations on both platforms. No iOS project or
image-generation inference implementation was found in the inspected tree.
Exact phone model and offline requirements are pending. These determine the
local generation model memory budget. Command-line GitHub authentication failed
with HTTP 401; the connected GitHub app remains available for publication.
