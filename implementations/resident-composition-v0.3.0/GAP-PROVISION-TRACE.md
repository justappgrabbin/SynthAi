The user clarified that adaptation serves each person's evolving purposes. The qualitative contribution is fixing the missing function and relieving burden, not merely detecting or naming a gap. No single goal is a ceiling.

Reuse: ComplementaryGapModel owns recorded human friction; SynthiaUnit owns the existing executable tool registry; LivingLoop supplies pulses; LocalMemory supplies persistence. No replacement engine or backend was introduced.

A life pulse checks open complementary gaps against registered complement:<capability> supports. Available supports run without requiring a prior human-success reward budget. SynthiaUnit.provisionHumanGap can also invoke the same path directly with execution context and a verifier. Verification can be supplied by a support's verifyRepair method. The verifier must return pass:true with evidence; a tool's success flag alone leaves the gap open. This verifies a particular function, not overall human success or subjective burden relief.

Every attempt records support identity, observation count, execution result, verification, and timestamps. Failures and unverified provisions remain pending across reloads. Concurrent requests share an attempt. Automatic retry requires a new gap observation; explicit provision remains available. This prevents repeated side effects every pulse. Pending work remains discoverable through complement.open()/snapshot().
