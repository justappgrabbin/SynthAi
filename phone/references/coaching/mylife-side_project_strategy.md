# 사이드 프로젝트 운영 전략

진행 중인 사이드의 운영 방식. 기능·로드맵이 아니라 운영 시스템.
"나와 맞는 사이드 방향 봐줘" 하면 질문 2~3개로 채워진다. 분기 1회 재평가.

## 운영 룰 (강제)

### 1. One Project Rule

- 한 분기 = 한 사이드만. 그 외는 안 한다
- 다른 사이드 충동이 오면 메모장만. 분기 끝까지 시작 안 함

### 2. 기획 동결

- 기획·전략 문서 추가 안 한다
- 실물(코드·런치·고객 대화)만 진전시킨다
- "기획서 한 번 더 다듬으면" = 시작 패턴 재발현

## 사이드는 본업 도피처가 아니다

본업 흔들림 → 불안 → 사이드 시작 → 본업 더 흔들림 → 반복.

룰: 본업 KPI 80%를 달성 못 하면 사이드 슬롯이 자동으로 본업으로 이동한다.

## 사이드 → 본업 전환 조건

사이드가 본업을 대체할 만큼 커지는 시점은 다음을 모두 충족할 때다.

1. 월 수익이 본업의 60% 이상으로 몇 달 연속
2. 활성 사용자가 목표선 위로 몇 달 연속
3. 내가 없어도 굴러가는 시스템 (자동화·외주·팀)
4. 분기 평가 3회 연속 합격

충족 전에는 본업이 협상 대상이 아니다.

## 위험 신호

| 신호 | 대응 |
|---|---|
| 새 사이드 시작 충동 | 메모장만, 분기 끝까지 안 시작 |
| 기획 문서 추가 욕구 | 실물 0줄 늘기 전엔 안 함 |
| 피봇 충동 | 외부 책임자와 30분 통화 후 결정 |
| 본업 슬롯 침범 | 즉시 사이드 슬롯 제로화 |
